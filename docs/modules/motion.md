# 连续运动与展示时钟

本模块把“车辆怎样移动”和“资源何时被占用”分开：模拟仍以可序列化的 `MotionSegment` 为真相，地图只按时间插值，不写回 `World`。

## 连续轨迹

- 新计划的轨道行驶由首尾相接的 `move` 段组成；相邻边之间没有固定 1 秒画面停顿。
- 上车 9 秒、下车 6 秒仍是实际 `boarding` / `alighting` 停留。
- 零距离调位保留一个兼容性的 `node` 段；它不属于沿轨道行驶。
- 旧存档中已有的逐节点 `node` 段仍合法，会按原时间表运行到终点；不会迁移或删除用户存档。

## 物理占用重建

`src/shared/trajectory.ts` 的 `requiredTrajectoryWindows` 只根据几何、段类型和时间重建要求，不信任段内或存档内声明的资源：

- 移动段预约实际选择的物理车道；单车道双向排他，2/3 车道分别预约，不按朝向划分。对角交叉共享冲突资源，具体规则见 [shared-lanes.md](shared-lanes.md)。
- 新计划同时预留连续移动路线的前/当前/后一段，保留对应车道与交叉安全空间；停站截断缓冲，不锁无关支路。缺省缓冲标记的旧在途计划仍按原间距完成，下一单才用新规则。
- 第一个出发点及每个到达节点拥有 `NODE_SECONDS + CLEARANCE_SECONDS` 的经过窗。下一条移动边可以在到达时刻立刻开始，所以预约不会制造画面停顿。
- 位于泊位点的节点窗同时预约泊位；上下车段在整个真实停留期间预约节点和泊位。
- 调度搜索、提交校验和存档物理冲突重建共用同一函数，避免三套占用规则漂移。
- 延迟发车时，Pod 在完整路径取得可行时隙之前一直预约原泊位；最终泊位仍是计划结束后的持久承诺。

这是有限规划窗内的空间—时间排他保证，不声称对任意路网证明无死锁；不可行或超出搜索边界的候选会返回等待原因。

## 平滑展示时钟

`src/shared/render-clock.ts` 在动画帧之间按 `TIME_SCALE × speed` 外推，并用最新 worker 快照限制领先量。普通整数快照只允许向前校正，不会每 100 ms 把车辆拉回。暂停会精确冻结在权威时间；恢复从该点继续。收到更小的权威时间视为载入或重置的新时间线，会立即切换，包括重新从 0 开始。

## 验证

`tests/motion.test.ts` 覆盖连续边时间、节点预约缺失拒绝、不同边共享节点的排他、旧 `node` 计划存档读取，以及 1× / 2× / 4× 时钟单调性、暂停和重置。
