# MVP 实施契约

本实现由 TypeScript 模拟、React/SVG 界面和一个 Web Worker 组成。Worker 是 World 的唯一写入者；UI 只读取快照并发送命令。World 可 JSON 序列化，不包含函数、Map 或 Infinity。

## 共享语义

时间以模拟秒计，从 07:00 的零点开始；1 秒现实时间推进 20 秒模拟时间，速度可为 1×、2×、4×。顶栏仅在显示时取整到 10 分钟，模拟与车辆插值不跳步。空间为 20 米网格。建筑占据 `x..x+w-1`、`y..y+h-1`；泊位点与 access 点之间的自动连接也需要预约。

每名居民最多一个 Journey，每辆 Pod 最多一个 ServicePlan。居民在室内有 `atBuildingId`，移动位置由 Journey/轨迹计算；Pod 发车前仍在起点泊位，服务结束才进入承诺的最终泊位。

建筑 `development` 保存容量、1/2/3 阶段、下一次入驻时刻、片区与布局、就业/商业角色和办公波次偏移。阶段开放比例为 50% / 75% / 100%；住宅新增住户受开放住宅容量、真实空缺岗位与全局居民上限共同约束。人数来自居民对象，容量和吸引力不是虚构客流。

增长模型 2 不再以四轮或 14 栋作为终点，扩张只增加地图边界，不移动旧坐标。旧存档通过 `initializeCityGrowth` 补齐元数据、解除旧完成标记；居民身份、既有目的地和在途计划保留。技术边界为 120 栋、1,200 人、160 Pod、256 格边长，达到边界用 `limited` 明示，不声称无限。

## 模块边界

- `src/network`：8 方向轨道图、建筑门、泊位接入、草稿校验、步行/轨道寻路和资源标识；纯读取。
- `src/population`：创建居民、生成下一活动、在纯步行与 Pod 方案间选择；不预约、不推进车辆、不依赖 UI。
- `src/scheduler`：构造并提交原子服务/调位计划；检查轨道、节点、对角交叉、泊位和有限停车尾部。候选失败不修改 World。
- `src/city`：增长、建设账本、补助、维护和完成行程统计；不推进车辆。
- `src/simulation`：Worker 内协调时间推进、命令、增长、经济、居民与 Pod 状态。
- `src/insights`：从 World 计算建筑意图、已完成行程和工作地点汇总；不写状态。
- `src/rendering`：独立 SVG 地图和连续位置显示；不发送模拟命令。
- `src/ui` / `src/app/bridge`：双语界面、检查器、工具、引导与 Worker 桥接。
- `src/persistence`：严格校验的本机保存、JSON 导入导出；载入后暂停。

## 改造与容量

暂停时可编辑轨道、平台和停车位；运行中改造进入待执行队列，待既有行程安全排空后提交。车道数为 1/2/3，全部双向共享；升级按增量收费。每个运营连通网络要求专用停车位数至少为 Pod 数量加一，平台不计入购买容量。旧存档停车不足时保留所有车辆、显示缺口，禁止继续扩大缺口。服务结束后预先承诺停车终点，闲置平台车辆会实际空驶让位。这些是保守的容量规则，不是任意网络无死锁或吞吐证明。

## 验收边界

测试与真实浏览器验收必须分别检查实体守恒、连续运动、有限终点、经济结算、保存恢复、增长和 UI。设计文档中的提案不自动等同于实现；当前已知待补验证项记录在 [VALIDATION.md](VALIDATION.md)。
