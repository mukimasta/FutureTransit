# MVP 实施契约

本实现由 TypeScript 模拟、React/SVG 界面和一个 Web Worker 组成。Worker 是 World 的唯一写入者；UI 只读取快照并发送命令。World 可 JSON 序列化，不包含函数、Map 或 Infinity。

## 共享语义

时间以模拟秒计，从 07:00 的零点开始；1 秒现实时间推进 30 秒模拟时间，速度可为 1×、2×、4×。顶栏逐分钟显示，1× 下每 2 实秒推进 1 模拟分钟；模拟仍按秒推进，车辆继续插值。空间为 40 米网格，步行时间、车辆时间、票价、运行费和轨道维护统一使用此物理尺度，不只放大显示里程。建筑占据 `x..x+w-1`、`y..y+h-1`；泊位点与 access 点之间的自动连接也需要预约。

每名居民最多一个 Journey，每辆 Pod 最多一个 ServicePlan。居民在室内有 `atBuildingId`，移动位置由 Journey/轨迹计算；Pod 发车前仍在起点泊位，服务结束才进入承诺的最终泊位。

建筑 `development` 保存容量、1/2/3 阶段、下一次入驻时刻、片区与布局、就业/商业角色和办公波次偏移。住宅、办公、商店、学校、医院、餐厅和公园构成实际需求地点；人数来自居民对象，容量和吸引力不是虚构客流。

增长模型 2 不再以四轮或 14 栋作为终点，扩张只增加地图边界，不移动旧坐标。站点版本使用保存键 `futuretransit-mvp-stations-v3`，World/JSON 信封仍为 v2。载入上一轮站点版本时丢弃停车位旧 `platformId` 标签，设施保持原位；更旧存档不迁移。技术边界为 120 栋、1,200 人、160 Pod、256 格边长，达到边界用 `limited` 明示，不声称无限。

## 模块边界

- `src/network`：8 方向轨道图、建筑门、泊位接入、草稿校验、步行/轨道寻路和资源标识；纯读取。
- `src/population`：创建居民、生成下一活动、在纯步行与 Pod 方案间选择，并记录可解释的最近出发决定；不预约、不推进车辆、不依赖 UI。
- `src/scheduler`：构造并提交原子服务/调位计划；检查轨道、节点、对角交叉、泊位和有限停车尾部。候选失败不修改 World。
- `src/city` / `src/economy`：增长、资产维护、实际公里票款、有限补助/贷款、分类账本和完成行程统计；不推进车辆。
- `src/simulation`：Worker 内协调时间推进、命令、增长、经济、居民与 Pod 状态。
- `src/insights`：从 World 计算建筑意图、已完成行程和工作地点汇总；不写状态。
- `src/rendering`：独立 SVG 地图和连续位置显示；不发送模拟命令。
- `src/ui` / `src/app/bridge`：双语界面、检查器、工具、引导与 Worker 桥接。
- `src/persistence`：严格校验的本机保存、JSON 导入导出；载入后暂停。

## 改造与容量

新建轨道、平台、停车位以及拓宽车道，在暂停和运行中均立即生效，不等待排空；拆除与移动已有设施仍等待涉及的行程排空。车道数为 1/2/3，全部双向共享；升级按增量收费。每个连通网络要求专用停车位数至少为 Pod 数量，平台不计入购买容量。不再强制多留一个周转位：服务计划可预约本车离开后的原停车位作为终点。额外停车位改善调位效率，但不是购车前置条件。服务结束后预先承诺停车终点，闲置平台车辆会实际空驶让位。这些是保守的容量规则，不是任意网络无死锁或吞吐证明。

`src/scheduler/expansion.ts` 在新增/扩容事务中保持所有既有计划的几何、时间、乘客与终点，只重建车道/节点预约后原子提交。`resourceModel: 2` 下，不同宽度走廊沿共用车道连续通行；新增支路保留原 `throughCorridors` 的贯通方向，转弯与换道需预约全部贯通车道。前/当前/后一段安全余量不变。拆除排空后清理失效的贯通元数据。存档允许旧模型但严格校验新增字段；旧预付拓宽队列在载入时立即完成，不重复收费。

平台可通过可选 `buildingId` 贴楼，也可独立放在空地。停车位没有建筑或平台归属：`add-parking {point, side}` 在指定空地点建一个车位和相邻接点，玩家铺轨接入；`add-parking {nearPlatformId, side}` 仅为站旁自动选址/接入的便捷命令，不存储归属关系，自动连接轨道单独收费。拆除平台不再要求先拆附近停车位，但仍执行真实在途占用与可达容量检查。

地图只有 `view` / `edit` 两种模式，Tab 切换。查看模式允许平移/缩放、实体点选、详情跳转与追踪，不显示设施修改按钮，Delete/建造入口也须校验编辑模式；详情跳转不自动切换模式。查看模式在拖动达到阈值后才捕获指针，避免吞掉设施点击；编辑模式点空地、建筑、泊位或轨道打开统一「铺轨 / 停车位 / 站点」菜单。`src/ui/editor.ts` 解析真实接轨点并生成鼠标方向预览，只有点击确认才提交命令。轨道使用最近端点，泊位使用外侧 access；贴楼站点保留 buildingId，停车位始终独立。既有网络旁新增泊位以所选节点为 access，空地则以所选格为泊位。草稿与方向预览是编辑子状态，Esc 返回菜单，切到查看取消未提交操作，但保留选中对象与追踪。三个主按钮使用相机反向缩放，保持至少 84×36px 的屏幕点击尺寸；建造依然由模拟层校验并扣费。

空格在窗口捕获阶段统一处理按下/释放，阻止聚焦按钮激活与页面滚动；自动重复不切换，输入控件/输入法组合及介绍弹窗除外。`toggle-pause` 在模拟侧切换真实暂停状态，快速按键不依赖 UI 旧快照；暂停覆盖居民、Pod、城市增长和经济时间推进。

## 经济与到达

开局现金为 2,600，票价为可调的每公里单价；每趟 Pod 在完成时按实际载客公里与该趟出发时锁定的单价收款。所有资产按城市分钟产生维护费，Pod 的空驶与载客移动都按实际公里产生运行费。三次手动补助后可借一笔固定贷款；补助、借款与还本不是经营利润。账本累计分类现金流并保留最后 300 条带符号明细。

使用本楼平台时，乘客从室内直达候车点，落客即进楼；使用附近站点时，居民实际步行到站，并在落客后步行到最终建筑。选择比较包含两端步行、候车、乘坐、票价；每端最多比较 3 个步行可达平台，限制大城市寻路成本。不引入街道或普通汽车。

借款 5,000 分 5 期、每个城市日一期；每期本金 1,000 加剩余本金的 2% 利息。按期归还合计利息 300（全期本金的 6%）；这是压缩的游戏融资周期，不是现实日利率。

## 验收边界

测试与真实浏览器验收必须分别检查实体守恒、连续运动、有限终点、经济结算、保存恢复、增长和 UI。设计文档中的提案不自动等同于实现；当前已知待补验证项记录在 [VALIDATION.md](VALIDATION.md)。
